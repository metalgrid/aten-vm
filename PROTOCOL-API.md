# Protocol integration API (updated: watch shutdown)

Implemented in `src/proto.rs`:

- `probe(host: &str, port: u16, slot: u8) -> Result<()>` (async): opens separate short status connection; checks count and rejects any occupied slot, even if the requested slot is free (conservative no-coexistence policy).
- `authenticate(&mut stream) -> Result<()>` (async): reads 17-byte type-2 acknowledgement, accepts payload[0]==0 only.
- `mount(&mut stream, slot) -> Result<()>` (async): sends exact 16-byte endpoint configuration; next frame is CBW, no second mount ACK.
- `serve(&mut stream, &mut tokio::fs::File, size: u64, slot: u8, &mut tokio::sync::watch::Receiver<bool>) -> Result<()>` (async): returns Ok on shutdown/server unplug, raw boxed io::Error on established-session network failures; descriptive non-io errors for disk/protocol failures, ambiguous response deadlines, and any disconnect before the first valid USBC command (mount not confirmed; do not retry).
- `unmount(&mut stream, slot) -> Result<()>` (async): sends native type-5 unplug request, flushes/half-closes output with a timeout. **Call after serve returns Ok; never after serve errors or cancelled writes.** Success confirms request transmission, not remote slot release. Input may be partially consumed on cancellation, so this final teardown does not parse an ACK using a fresh reader. Drop stream afterwards. Fresh probe can verify release.
- `read_frame(&mut AsyncRead) -> Result<Frame>` and `validate_auth(&Frame) -> Result<()>`; `Frame { kind: [u8;4], payload: Vec<u8> }`.

Generic stream bounds allow offline Tokio duplex tests; TcpStream call sites need no changes. Serve never selects shutdown against command writes: current response completes or fails within 20 seconds first. Persistent reader retains header/body state when a false watch update cancels a read. Main should not externally cancel serve.

Evidence: streams 0/3 status `0000000800000000` -> `000000090400000003ffffff`: 3 slots, all free. Native Core_GetDevStatusFromFW indexes payload[slot+1], ff means free. Stream 1 `0a` -> `0b` payload `5000` discovers HTTP port 80 (`GetHttpPortFromFW`), not capabilities, so unnecessary to direct media mount. Endpoint config is `00000007080000000603011002200330`; ISO size is answered in READ CAPACITY, not mount.

Captured command support: TEST UNIT READY, INQUIRY, READ CAPACITY(10), GET CONFIGURATION, READ(10). The full 19-descriptor GET CONFIGURATION table was extracted statically from native GetConfig at 0x25e35..0x26d95 (non-null-media branches); first 8 bytes agree with capture. REQUEST SENSE, START STOP, PREVENT ALLOW, and MODE SENSE(6/10) added. MODE SENSE supports pages 0/2a/3f, current/default/changeable, no subpages: standard read-only headers and native pagecode_2ah values (0x2840f), not capture-verified. Unsupported pages/opcodes return CHECK CONDITION, unsupported host-to-device data transfers terminate without writing ISO. No claim of a complete MMC implementation (e.g. READ TOC, READ(12), GET EVENT STATUS not implemented). Unplug type5, remote unplug type6, and keepalive4 -> type3/ffffffff are native-disassembly-derived, not in the 11-second capture.

Offline verification: replay test compares all 88 reassembled PDUs after auth request in stream 2 byte-for-byte: 34 SCSI commands, 15 sectors (30,720 bytes), including exact INQUIRY/configuration/capacity/CBW tags/CSWs. Tests also cover fragmentation/coalescing/truncation/oversized frames, cancelled reads, shutdown during a blocked response, sense/bounds/residue/phase errors, disk error classification, 69-sector multi-chunk reads, native keepalive, and pre-mount vs established disconnect classification. `cargo test --offline` and `cargo clippy --offline --all-targets -- -D warnings` are local only; no BMC/network access performed.
